## Big idea

A **tuple** is a row of values kept in order, just like a list. The big difference: once a tuple is made, it can't be changed. You can't add, remove or replace its items. A value that can't be changed is called **immutable**; a list, which can change, is **mutable**.

```python
birthday = (14, "March", 1990)
print(birthday)
print(birthday[1])
```

```output
(14, 'March', 1990)
March
```

Tuples use round brackets where lists use square ones. They suit data that belongs together and shouldn't change, like a date or a map position.

## Walkthrough

### Creating tuples

A tuple can be empty, hold one item, or hold many:

```python
empty = ()
also_empty = tuple()
colors = ("red", "green", "blue")
no_brackets = 1, 2, 3
print(empty, also_empty, colors, no_brackets)
```

```output
() () ('red', 'green', 'blue') (1, 2, 3)
```

It is really the **commas** that make a tuple, not the brackets. That is why a one-item tuple needs a trailing comma. Without it, the brackets are just ordinary grouping brackets, like in maths:

```python
one = ("tea",)
not_a_tuple = ("tea")
print(type(one), len(one))
print(type(not_a_tuple))
```

```output
<class 'tuple'> 1
<class 'str'>
```

`tuple()` can also turn another collection into a tuple: `tuple([1, 2])` gives `(1, 2)`, and `tuple("hi")` gives `('h', 'i')`.

### Indexing and slicing

Reading a tuple works exactly like reading a list: index from 0 at the front or -1 at the back, and slice with `[start:stop:step]`. A slice of a tuple is a new tuple:

```python
planets = ("Mercury", "Venus", "Earth", "Mars", "Jupiter")
print(planets[0], planets[-1])
print(planets[1:3])
print(planets[::2])
print(planets[::-1][:2])
```

```output
Mercury Jupiter
('Venus', 'Earth')
('Mercury', 'Earth', 'Jupiter')
('Jupiter', 'Mars')
```

`len()`, `in`, `not in` and `for` loops all work on tuples too. So do two read-only methods, `index()` and `count()`:

```python
dice = (3, 6, 1, 6, 2)
print(len(dice), 6 in dice, dice.index(6), dice.count(6))
```

```output
5 True 1 2
```

### Immutability, and tuples vs. lists

Trying to change an item fails with a `TypeError`. Tuples also have no `append()`, `remove()` or `sort()` methods:

```python
point = (4, 7)
point[0] = 5
```

```error
TypeError: 'tuple' object does not support item assignment
```

What you **can** do is build a new tuple and give it the old name. `+` joins tuples and `*` repeats one:

```python
sizes = ("S", "M")
sizes = sizes + ("L",)
print(sizes)
print(("ha",) * 3)
```

```output
('S', 'M', 'L')
('ha', 'ha', 'ha')
```

The variable `sizes` now points at a brand-new tuple; the old one was not changed.

Splitting a tuple into separate variables is called **unpacking**. It is one of the most common things you do with tuples:

```python
city = ("Lisbon", 38.7, -9.1)
name, lat, lon = city
print(name, lat)
```

```output
Lisbon 38.7
```

| | List | Tuple |
|---|---|---|
| Brackets | `[1, 2]` | `(1, 2)` |
| Can change after creation | Yes (mutable) | No (immutable) |
| Methods | many: `append()`, `sort()`, ... | only `count()` and `index()` |
| Typical use | a collection that grows or changes | a fixed record, like a date or coordinates |
| Can be a dictionary key | No | Yes, if its items are immutable too |

### Nesting: collections inside collections

A tuple can hold lists and other tuples, and a list can hold tuples:

```python
menu = (("soup", 4.5), ("salad", 6.0))
orders = [("Ana", "soup"), ("Ben", "salad")]
mixed = (["pen", "ink"], 3)
print(len(menu), len(orders), mixed)
```

```output
2 2 (['pen', 'ink'], 3)
```

A tuple only stops you from replacing **its own** items. If one of those items is a list, the list itself can still change:

```python
backpack = (["map", "water"], "blue")
backpack[0].append("snack")
print(backpack)
```

```output
(['map', 'water', 'snack'], 'blue')
```

### Indexing into nested tuples

Use one index per level, just like with nested lists:

```python
recipes = (("pancakes", ("flour", "milk", "eggs")), ("toast", ("bread", "butter")))
print(recipes[0][0])
print(recipes[0][1][2])
print(recipes[-1][1][-1])
```

```output
pancakes
eggs
butter
```

## Common mistakes

**Forgetting the comma in a one-item tuple.** `("tea")` is just the string `"tea"`. Write `("tea",)`.

**Calling list methods on a tuple.**

```python
days = ("Mon", "Tue")
days.append("Wed")
```

```error
AttributeError: 'tuple' object has no attribute 'append'
```

**Deleting one item.** `del` works on a whole tuple variable, but not on one of its items:

```python
days = ("Mon", "Tue")
del days[0]
```

```error
TypeError: 'tuple' object doesn't support item deletion
```

**Unpacking into the wrong number of names.**

```python
size = (30, 40, 50)
width, height = size
```

```error
ValueError: too many values to unpack (expected 2, got 3)
```

## Exam traps

- **`(x)` vs. `(x,)`.** `type((7))` is `int`, `type((7,))` is `tuple`. And `t = 1,` makes a tuple with no brackets at all.
- **Immutable doesn't mean "frozen all the way down".** A list inside a tuple can still be appended to; only replacing `t[i]` is forbidden.
- **`+=` on a tuple.** `t += (4,)` works, because it builds a new tuple and rebinds `t`. It doesn't change the old tuple.
- **Slicing returns a tuple.** `(1, 2, 3)[0:1]` is `(1,)`, while `(1, 2, 3)[0]` is `1`.
- **Errors to name.** Item assignment raises `TypeError`; calling `append()` raises `AttributeError`; an index past the end raises `IndexError`.
