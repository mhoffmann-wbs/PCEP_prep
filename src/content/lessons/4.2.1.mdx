## Big idea

Some problems only show up while a program **runs**: dividing by a number that happens to be zero, asking for the 10th item of a list with 3 items, or turning the text `"ten"` into a number. When Python meets such a problem, it **raises an exception**: it creates an object that describes what went wrong and stops the normal flow of the program.

If nothing handles the exception, the program ends and Python prints a **traceback**, an error report. Read it from the **bottom**: the last line names the exception type and explains the problem.

```python
price = int("ten")
```

```error
ValueError: invalid literal for int() with base 10: 'ten'
```

Here `ValueError` is the **exception type**, and the text after the colon is the **message**.

## Walkthrough

### Why exceptions exist

A program can't always know in advance whether an operation will work. The user may type letters instead of digits, or a file may be missing. Exceptions give Python a clear way to say "I can't do this" instead of carrying on with a wrong value.

They also give **you** a choice. You can let the program stop and show the error, which is useful while you are fixing your code. Or you can **catch** the exception and react to it, for example by asking the user again. Catching is the topic of the next lesson, [Handle runtime exceptions](/learn/4.2.2).

### An exception interrupts the flow

Normally Python runs one line after another. When a line raises an exception, Python **stops right there**. The rest of that line and every line after it are skipped:

```python
print("Step 1: open the recipe")
eggs_per_cake = 3
cakes = 0
print("Step 2: eggs per cake is", eggs_per_cake / cakes)
print("Step 3: bake")
```

```error
ZeroDivisionError: division by zero
```

Before the program stops, it prints `Step 1: open the recipe`, but never `Step 3`. Even the `print` on the failing line doesn't print anything, because Python had to work out its argument first.

An exception raised inside a function stops the function too, and then the code that called it. Nothing after the failing line runs:

```python
def average(marks):
    return sum(marks) / len(marks)

print("Start")
print(average([]))
print("End")
```

```error
ZeroDivisionError: division by zero
```

This prints `Start` and then stops: `End` never appears.

### Six exceptions to know

PCEP expects you to look at a line of code and say which exception it raises. These six cover most of it.

**`ValueError`**: the value has the right **type**, but an unusable **content**. Typical case: converting text that isn't a number.

```python
age = int("12.5")
```

```error
ValueError: invalid literal for int() with base 10: '12.5'
```

**`TypeError`**: the operation doesn't work with this **type** of value at all, for example adding text and a number.

```python
apples = 4
print("Apples: " + apples)
```

```error
TypeError: can only concatenate str (not "int") to str
```

Calling a function with the wrong number of arguments is also a `TypeError`:

```python
print(len("tea", "coffee"))
```

```error
TypeError: len() takes exactly one argument (2 given)
```

**`ZeroDivisionError`**: dividing by zero with `/`, `//` or `%`.

```python
slices = 8
people = 0
print(slices // people)
```

```error
ZeroDivisionError: division by zero
```

**`IndexError`**: asking a list, tuple or string for a position that doesn't exist.

```python
weekdays = ["Mon", "Tue", "Wed"]
print(weekdays[5])
```

```error
IndexError: list index out of range
```

**`KeyError`**: asking a dictionary for a key it doesn't have. The message is the missing key.

```python
prices = {"bread": 2.5, "milk": 1.2}
print(prices["cheese"])
```

```error
KeyError: 'cheese'
```

**`NameError`**: using a name Python doesn't know, often because of a typo or a missing assignment.

```python
temperature = 21
print(temprature)
```

```error
NameError: name 'temprature' is not defined
```

### Which operation raises which exception

| Operation | Exception |
|---|---|
| `int("abc")`, `float("hello")` | `ValueError` |
| `"5" + 5`, `len(42)`, calling with too many arguments | `TypeError` |
| `10 / 0`, `10 // 0`, `10 % 0` | `ZeroDivisionError` |
| `my_list[99]`, `"cat"[3]` | `IndexError` |
| `my_dict["missing"]` | `KeyError` |
| using an unknown or misspelled name | `NameError` |

A good question to ask: **is the type wrong, or the value?** `int("abc")` gets a string, and `int()` does accept strings, so the type is fine; only the content is bad, which makes it a `ValueError`. `"5" + 5` mixes two types that `+` can't combine, so it's a `TypeError`.

### Exceptions vs. syntax errors

A `SyntaxError` is different: Python finds it while **reading** the code, before running anything, so not even the first line runs. The exceptions in this lesson happen while the program **runs**, so the lines before the problem do run. Syntax errors are covered in [Python program structure](/learn/1.2.1).

## Common mistakes

**Doing maths with `input()` without converting.** `input()` always returns a string, so adding a number to it is a `TypeError`:

```python
guests = input("How many guests? ")
print(guests + 1)
```

```input
4
```

```error
TypeError: can only concatenate str (not "int") to str
```

Convert first: `guests = int(input("How many guests? "))`.

**Reading only the top of the traceback.** The useful part is the **last** line: the exception type and its message.

**Confusing `KeyError` and `IndexError`.** A missing dictionary **key** raises `KeyError`. A list position that is too large raises `IndexError`.

**Expecting `int()` to round.** `int("7.9")` doesn't give 7: the text isn't a whole number, so it raises `ValueError`. `int(7.9)` on a float works and gives 7.

```python
print(int(7.9))
print(int("7.9"))
```

```error
ValueError: invalid literal for int() with base 10: '7.9'
```

## Exam traps

- **Output before the error.** Questions often print a few lines and then fail. Everything before the failing line is printed; nothing after it is.
- **`ValueError` vs. `TypeError`.** `int("hi")` is a `ValueError` (bad content); `"hi" + 1` is a `TypeError` (types that don't fit together).
- **`/`, `//` and `%` by zero** all raise `ZeroDivisionError`, also with floats such as `5.0 / 0`.
- **Missing key vs. missing index.** `d["x"]` raises `KeyError`; `lst[10]` raises `IndexError`. A **slice** past the end, `lst[5:10]`, raises nothing.
- **Misspelled names** raise `NameError`, including built-ins with wrong capitals, such as `Print("hi")`.
- **Strings are sequences.** `"tea"[3]` raises `IndexError` just like a list.
